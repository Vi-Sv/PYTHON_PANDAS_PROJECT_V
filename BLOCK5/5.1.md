БЛОК 5. АГРЕГАЦИЯ И ОКОННЫЕ МАГИСТРАЛИ (МЕТОД ЗЕРКАЛА SQL) [91.24]Пункт 5.1. Группировка через .groupby() и метод агрегации .agg(). Построение плоских Pivot-матриц (Conditional Pivot Aggregation на Python) [91.11, 91.24].Мы открываем финальный, самый мощный ящик нашей коробки. Здесь твоё «нестандартное зрение» и выжженная база SQL соединяются в единый вычислительный контур [91.24]. Твоя задача на этом верстаке — научиться сжимать миллионные транзакционные логи до уровня плоских, стерильных аналитических матриц.Мы разберем, как устроен механизм группировки внутри оперативной памяти (RAM) [91.24], и зеркально перенесем технологию Conditional Pivot Aggregation из твоего прорывного Кейса №33 на рельсы Python Pandas [91.11, 91.24].АНАТОМИЯ ИНСТРУМЕНТА: АЛГОРИТМ SPLIT-APPLY-COMBINEКогда ты вызываешь в Pandas метод .groupby(), в оперативной памяти компьютера не происходит мгновенного подсчета сумм. Процессор запускает фундаментальный трехфазный конвейер Split-Apply-Combine (Разделение — Применение — Объединение).                  Конвейер .groupby() под капотом RAM:
                  
  [Сырой лог] ──>  ФАЗА 1: SPLIT         ──> ФАЗА 2: APPLY      ──> ФАЗА 3: COMBINE

  | ИТ  │ 100 |    | ИТ  │ [100, 150]    |   | ИТ  │ SUM -> 250  |   [Финальная витрина]
  | АВТО│  40 | ➔  |     │               | ➔ |     │             | ➔ | ИТ   │ 250 │
  | ИТ  │ 150 |    | АВТО│ [40]          |   | АВТО│ SUM -> 40   |   | АВТО │  40 │
1. Физика трех фаз конвейера в RAMФаза 1: Split (Разделение). Pandas сканирует столбец, по которому идет группировка (например, category). На основе хэш-таблицы он находит уникальные ключи и молча группирует индексы строк в изолированные виртуальные контейнеры памяти. На этом этапе в консоли появляется объект типа DataFrameGroupBy — это «замерший цех», готовый к работе.Фаза 2: Apply (Применение). К каждому изолированному контейнеру строк применяется математическая функция (сумма, среднее, количество), которую ты указал. Вычисления происходят параллельно и на огромной скорости векторов NumPy.Фаза 3: Combine (Объединение). Результаты вычислений из всех контейнеров склеиваются обратно в единую плоскую результирующую матрицу, где уникальные ключи группировки становятся новым строковым индексом.2. Инженерный стандарт агрегации: Метод .agg()Никогда не пиши кустарные конструкции вида df.groupby('key')['volume'].sum(). Это лишает тебя гибкости. Промышленный стандарт — использование прецизионного метода агрегации .agg(), который принимает словарь настроек и позволяет за один проход рассчитать разные метрики для разных столбцов.pythonimport pandas as pd

# Сжатие лога снабжения до уровня чистой аналитической витрины
summary_df = df.groupby("category", as_index=False).agg(
    total_volume=("quantity_fact", "sum"),    # Считаем сумму по объемам
    average_price=("price_per_unit", "mean"),  # Считаем среднюю цену поставки
    orders_count=("log_id", "count")           # Считаем число транзакций
)
Используйте код с осторожностью.Флаг as_index=False: Команда принуждает Pandas не превращать столбец группировки category в строковый индекс, а оставить его обычной плоской колонкой. Это идеальное зеркало SQL-вывода, готовое к мгновенной заливке в базу или BI [91.24].3. Зеркало Кейса №33: Conditional Pivot Aggregation на PythonВ Кейсе №33 ты применил технологию плоского условного сумматора SUM(CASE WHEN...), чтобы одним проходом сжать транзакционный лог категорий до уникальных пользователей и убрать избыточные Index Scan на сервере [91.11, 91.24]. В Pandas эта логика реализуется через комбинацию условной маски np.where и группировки.pythonimport numpy as np

# 1. Разворачиваем на лету горизонтальные реле (CASE WHEN из SQL)
df["cost_it"] = np.where(df["category"] == "it", df["quantity_fact"] * df["price_per_unit"], 0)
df["cost_auto"] = np.where(df["category"] == "auto", df["quantity_fact"] * df["price_per_unit"], 0)

# 2. Однопроходное схлопывание матрицы в RAM по уникальным пользователям (GROUP BY)
pivot_matrix = df.groupby("user_id", as_index=False).agg(
    total_cost_it=("cost_it", "sum"),
    total_cost_auto=("cost_auto", "sum")
)
Используйте код с осторожностью.Физика в RAM: Мы не плодим циклы. Процессор выполняет быструю векторную проверку маски через np.where [91.24], мгновенно заливая нули в несовпадающие ячейки, а затем метод .groupby().agg() за один физический проход сжимает матрицу до уникальных user_id. На выходе — стерильный плоский Pivot, защищенный от логического раздувания строк [91.24].ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)Капкан «Невидимого размножения строк» из-за пропущенной зачистки текста:Если перед запуском конвейера .groupby() ты забыл провести текстовую дезинфекцию, которую мы учили в Пункте 4.2 (.str.strip().str.lower()), алгоритм Split отработает строго по факту [91.24].В чем дефект: Значения 'IT ' (с пробелом) и 'it' уйдут в два разных контейнера памяти. На финальной витрине появятся дублирующиеся строки для одной и той же категории, математический баланс отчета сойдется неверно, а бизнес-заказчик увидит искаженную аналитику [91.24].Инструмент защиты: Входной контроль (ОТК) текстовых полей перед группировкой — закон.Ловушка исчезновения NaN при группировке:По умолчанию Pandas при вызове .groupby() полностью игнорирует и выбрасывает строки, у которых в столбце группировки сидит пустота NaN/None.В чем дефект: Если у тебя в логе снабжения у 500 транзакций не была указана категория, эти объемы просто бесшумно испарятся из итоговой витрины, занижая реальные затраты компании.Инструмент защиты: Всегда явно указывай параметр-перехватчик dropna=False. Он принудительно создаст под пустые значения отдельную строковую группу на витрине, и ты сразу увидишь объем неклассифицированного хаоса:pythondf.groupby("category", as_index=False, dropna=False).agg(...)
