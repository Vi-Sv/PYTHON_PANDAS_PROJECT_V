### ИНСТРУМЕНТ №1: ВЕКТОРНЫЙ ПЕРЕНОС СМЫСЛОВ — МЕТОД .TRANSFORM()

Когда ты используешь обычный `.groupby().agg()`, таблица неизбежно схлопывается — строки сжимаются до уникальных ключей [91.24]. Но в оконных функциях SQL тебе нужно рассчитать агрегат (например, среднегодовую цену категории) и **прописать её в каждую детальную строку исходной таблицы**, не разрушая её длину. Для этого в Pandas существует метод `.transform()`.

#### 1. Физика в RAM (Зеркальное отображение PARTITION BY)
Метод `.transform()` выполняет ту же трехфазную конвейерную сборку Split-Apply, но на этапе Combine он совершает архитектурный маневр: берет посчитанный агрегат группы и **дублирует его (размножает вектор)** до исходного количества строк этой группы.

```python
import pandas as pd

# Вычисление среднего объема по категориям без схлопывания таблицы
# Это чистый аналог: AVG(quantity_fact) OVER(PARTITION BY category)
df["avg_category_volume"] = df.groupby("category")["quantity_fact"].transform("mean")
```
*   **Физика в RAM:** Вектор результатов имеет длину, строго равную длине исходного датафрейма `df`. Процессор мгновенно сопоставляет индексы строк и прописывает агрегаты. Теперь в рамках каждой строки ты можешь «на лету» вычислить отклонение: `df['quantity_fact'] - df['avg_category_volume']`.

### ИНСТРУМЕНТ №2: СКОЛЬЗЯЩИЙ МАРШ — МЕТОД .ROLLING()

Если `.transform()` рассчитывает статичную метрику на всю группу, то метод `.rolling()` создает динамическое «окно», которое скользит по строкам таблицы сверху вниз, пересчитывая показатели внутри заданного временного или строкового интервала.

#### 1. Расчет нарастающего итога (Running Total)
Для вычисления накопленного объема поставок по дням или складам мы комбинируем группировку и встроенный накопитель `.cumsum()` (Cumulative Sum) [91.11, 91.24]:
```python
# Чистый аналог: SUM(quantity_fact) OVER(PARTITION BY warehouse_id ORDER BY supply_date)
# Предварительно сортируем таблицу по дате для строгого соблюдения хронологии!
df = df.sort_values(by=["warehouse_id", "supply_date"])
df["running_total_volume"] = df.groupby("warehouse_id")["quantity_fact"].cumsum()
```

#### 2. Расчет скользящего среднего (Moving Average)
Для сглаживания сезонных всплесков поставок и выявления жестких трендов мы запускаем скользящее окно фиксированного размера (например, окно в 3 строки):
```python
# Скользящее среднее внутри каждой группы
df["moving_avg_3_days"] = df.groupby("warehouse_id")["quantity_fact"].rolling(window=3).mean().reset_index(level=0, drop=True)
```
*   **Физика в RAM:** Алгоритм встает на Строку 2, захватывает Строку 0, 1 и 2, считает среднее. Сдвигается на Строку 3 — захватывает Строку 1, 2 и 3, считает среднее. Первые ячейки группы, где физически не хватает данных для заполнения размера окна, автоматически зальются маркером `NaN`.

### ЗЕРКАЛО SQL

Вся оконная магистраль в Pandas — это прямое, посимвольное отображение оконного интерфейса СУБД:
*   Команда `df.groupby("category")["quantity_fact"].transform("mean")` — это:
    ```sql
    SELECT AVG(quantity_fact) OVER(PARTITION BY category) FROM supply_logs;
    ```
*   Команда `.rolling(window=3).mean()` — это скользящее окно с жесткими границами строк:
    ```sql
    SELECT AVG(quantity_fact) OVER(
        PARTITION BY warehouse_id 
        ORDER BY supply_date 
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) FROM supply_logs;
    ```

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1.  **Капкан «Разрушения хронологии» (Смерть нарастающего итога):**
    В отличие от SQL, где внутри блока `OVER()` ты жестко прописываешь `ORDER BY`, методы `.cumsum()` и `.rolling()` в Pandas **не умеют автоматически сортировать данные внутри окна**. Они считают строго по текущему физическому порядку строк в RAM [91.24].
    *   *В чем дефект:* Если во входящем грязном файле даты поставок перемешаны хаотично, нарастающий итог посчитается с нарушением временной логики. Баланс остатков на складах будет полностью уничтожен.
    *   *Инструмент защиты (ОТК):* Перед запуском любой скользящей или накопительной функции **всегда принудительно сортируй весь датафрейм** по ключам группы и хронологическому полю:
    ```python
    # Железная стабилизация контура перед расчетом окон
    df = df.sort_values(by=["warehouse_id", "supply_date"], ascending=[True, True])
    ```

### КРАТКИЙ ИНВЕНТАРНЫЙ ИТОГ ДЛЯ ТВОЕЙ КОРОБКИ:
*   **`.transform('функция')`** — вычисляет агрегат группы (`PARTITION BY`), но не сжимает таблицу, а дублирует результаты в каждую строку исходной длины [91.24].
*   **`.cumsum()`** — скоростной векторный инструмент для расчета нарастающих итогов (`Running Total`) [91.11, 91.24].
*   **`.rolling(window=N)`** — скользящее аналитическое реле для расчета трендов и средних (`Moving Average`) [91.11, 91.24].
*   **Предварительный `sort_values()`** — твой бескомпромиссный закон. Без сортировки оконный расчет по хронологии превращается в мусор.
