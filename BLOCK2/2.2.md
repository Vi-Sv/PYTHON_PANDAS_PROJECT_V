### АНАТОМИЯ ИНСТРУМЕНТА: КАСКАД ИЗВЕСТНЫХ ВЕКТОРОВ

Большинство воспринимает `DataFrame` просто как «цифровую Excel-таблицу». На самом деле `DataFrame` под капотом оперативной памяти — это **Словарь (`dict`)**, в котором:
* **Ключами** являются названия столбцов (объект `Columns`).
* **Значениями** являются уже изученные нами объекты `Series`, подвешенные на один общий, монолитный для всей таблицы **строковый Индекс (`Index`)**.

Структура DataFrame в RAM (Вид сверху):Индекс (Index)  ──>  Ключ "material_id" (Series)  │  Ключ "quantity" (Series)[ "строка_0" ]  ──>  [ Ячейка 0: 102           ]  │  [ Ячейка 0: 15.5        ][ "строка_1" ]  ──>  [ Ячейка 1: 105           ]  │  [ Ячейка 1: 40.0        ]#### 1. Физика в RAM (Столбчатая природа памяти)
Из-за того, что `DataFrame` — это каскад вертикальных `Series`, Pandas физически хранит данные в RAM **по столбцам (Column-store логика)**. Каждая колонка — это изолированный, однородный массив памяти.
* **Почему это критично:** Добавить новый столбец или провести операцию над целой колонкой (например, умножить весь объем на коэффициент) — это сверхбыстрая векторная операция, не требующая перебора строк. Но если ты начнешь обрабатывать `DataFrame` горизонтально, перебирая его построчно через циклы, компьютер будет вынужден на каждом шаге собирать новый временный объект, что мгновенно вызовет перегрев процессора и паралич оперативной памяти.

#### 2. Тотальное уничтожение путаницы с осями (axis=0 vs axis=1)
Когда ты вызываешь методы фильтрации, удаления или расчета средних (например, `.drop()` или `.sum()`), Pandas требует указать ось: `axis=0` или `axis=1`. Это главная ловушка для ума. Давай выжжем эту путаницу раз и навсегда через физическую логику направления движения.

*   **`axis=0` (Направление: СВЕРХУ ВНИЗ) — Ось Строк.** 
    Когда ты указываешь `axis=0` (или `axis='index'`), ты приказываешь алгоритму двигаться **вертикально**, проваливаясь сквозь строки.
    * *Пример:* `df.sum(axis=0)` заставит алгоритм пройтись сверху вниз по каждой колонке и выдать сумму по строкам для каждого столбца.
*   **`axis=1` (Направление: СЛЕВА НАПРАВО) — Ось Столбцов.**
    Когда ты указываешь `axis=1` (или `axis='columns'`), ты приказываешь алгоритму двигаться **горизонтально**, пересекая границы столбцов.
    * *Пример:* `df.sum(axis=1)` заставит алгоритм просуммировать значения в рамках одной строки слева направо и выдать результат для каждой строки индивидуально.

axis=0 (Движение вниз, сквозь строки ⬇️)┌───────────┐│ Строка 0  │  ──> axis=1 (Движение вправо, сквозь колонки ➡️)├───────────┤│ Строка 1  │└───────────┘

#### 3. Зеркало SQL
По своей физической структуре в оперативной памяти `DataFrame` в Pandas ближе всего стоит к **Колоночным СУБД (Columnar Databases), таким как ClickHouse**. 
В отличие от PostgreSQL, которая пишет данные на диск целыми строками (Row-store), ClickHouse и Pandas хранят каждую колонку изолированно друг от друга. Именно поэтому операции агрегации и фильтрации по конкретным столбцам в Pandas происходят со скоростью света — процессору не нужно читать лишние байты соседних колонок.

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1. **Капкан скрытого разрушения типов при добавлении «разнородной» строки:**
   Поскольку `DataFrame` — это каскад вертикальных `Series`, попытка добавить одну строку с грязными типами данных на лету разрушит структуру колонок.
   ```python
   # Если в чистую числовую таблицу df добавить строку, где в столбце объема стоит текст:
   df.loc["грязная_строка"] = [102, "нет_данных"]
   ```
   * *В чем дефект:* Колонка объема мгновенно потеряет числовой тип данных `int64/float64` и превратится в тяжелый ссылочный тип `object`. Произойдет лавинообразное раздувание RAM, а все последующие математические функции на этой таблице упадут с ошибкой [91.24].
   * *Инструмент защиты:* Никогда не собирай `DataFrame` построчно. Сначала очищай и накапливай данные в виде плоских списков или словарей в памяти, и только затем создавай финальный `DataFrame` за один проход.

2. **Ловушка «Исчезновения столбца» при неправильной оси:**
   Если тебе нужно удалить столбец с грязными логами `error_code`, и ты ошибешься в оси:
   ```python
   df.drop("error_code", axis=0) # Капкан!
   ```
   * *Результат:* Программа аварийно рухнет с ошибкой `KeyError`, потому что при `axis=0` Pandas начнет искать метку `"error_code"` среди строковых индексов (вертикально), а не среди столбцов.
   * *Стерильный код:* Всегда явно указывай ось столбцов через ключевые слова, чтобы код читался как монолитная спецификация:
   ```python
   df = df.drop(columns=["error_code"]) # Абсолютная защита от путаницы осей
   ```

### КРАТКИЙ ИНВЕНТАРНЫЙ ИТОГ ДЛЯ ТВОЕЙ КОРОБКИ:
* **`DataFrame`** — это словарь вертикальных колонок-Series, посаженных на единый цепной строковый индекс.
* Память организована по столбцам. Операции над колонками — моментальные; горизонтальный перебор через циклы — запрещен [91.24].
* **`axis=0`** — движение вектора идет сверху вниз (по строкам) [91.24].
* **`axis=1`** — движение вектора идет слева направо (по столбцам) [91.24].
