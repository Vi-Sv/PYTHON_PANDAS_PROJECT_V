# БЛОК 2. ФУНДАМЕНТ PANDAS: СТРУКТУРЫ SERIES И DATAFRAME
## Пункт 2.1. Анатомия Series: Индекс как жесткий внутренний ключ и Вектор значений. Физический износ памяти.

Мы открываем второй ящик нашей коробки и переходим к детальному разбору фундаментальной структуры библиотеки Pandas — объекту `Series`. Если ты поймешь физическую анатомию `Series`, то вся остальная магия Pandas (включая таблицы `DataFrame`) разложится в твоей голове на простейшие составляющие.

Забудь про восприятие `Series` как «просто колонки». Положим этот инструмент на верстак и разберем его до последнего байта.

---

### АНАТОМИЯ ИНСТРУМЕНТА: КЕНТАВР ИЗ СЛОВАРЯ И МАССИВА

Объект `Series` под капотом — это неделимый гибрид, состоящий из двух мощных физических контуров в оперативной памяти:
1. **Индекс (`Index`)** — жесткая хэшированная структура (полная копия логики словаря `dict`), хранящая уникальные метки-ключи.
2. **Вектор значений (`Values`)** — непрерывный, однородный массив данных (под управлением низкоуровневой библиотеки `NumPy`), хранящий сами значения в памяти компьютера.

Структура Series в RAM:Индекс (Хэш-карта, логика Dict)  ──>  Вектор значений (Непрерывный массив NumPy)[ Метка "стык_01" (Хэш) ]        ──>  [ Ячейка 0: "Принято" ][ Метка "стык_02" (Хэш) ]        ──>  [ Ячейка 1: "Дефект"  ]
#### 1. Физика в RAM (Физический износ и однородность памяти)
Когда ты создаешь `Series`, Pandas жестко связывает индекс со значениями:
```python
import pandas as pd

joints = pd.Series(data=["Принято", "Дефект"], index=["стык_01", "стык_02"])
```
Вектор значений (`Values`) требует **абсолютной однородности типов (Homogeneous data)**. Если ты объявил, что в векторе лежат целые числа (`int64`), компьютер выделяет под каждую ячейку ровно 8 байт непрерывной памяти. Это позволяет процессору выполнять векторные вычисления со скоростью света. 
* Если в одну из ячеек числового вектора при очистке данных случайно просочится текстовая строка, Pandas мгновенно разрушит монолитную структуру памяти и приведет весь вектор к типу `object` (ссылочный тип данных). Это резко увеличивает физический износ памяти: потребление RAM вырастает в 3–5 раз, а скорость математических расчетов падает на порядки.

#### 2. Магия неявного выравнивания по индексу
Индекс в `Series` — это не просто декорация, это **автоматический замок**. Если ты производишь математическое действие с двумя объектами `Series`, Pandas выполняет операцию не по физическому порядку строк, а по **совпадению меток индекса**.

```python
plan = pd.Series([10, 20], index=["участок_A", "участок_B"])
fact = pd.Series([15, 8],  index=["участок_B", "участок_A"])

# Сложение произойдет по ключам, а не по порядку!
balance = fact - plan
# Результат: участок_A станет -2 (8 - 10), а участок_B станет 5 (15 - 20)
```

#### 3. Зеркало SQL
Объект `Series` — это зеркальное отображение **одноколоночного индексированного представления (View)** или результата работы оконной функции с жестким ключом секционирования.
Когда в SQL ты пишешь:
```sql
SELECT quantity FROM supply_logs WHERE material_id = 102;
```
Если `material_id` — это твой уникальный ключ (индекс), то возвращенный столбец `quantity` в оперативной памяти сервера ведет себя точно так же, как `Series`: у каждой цифры есть жесткая привязка к своему ключу, по которому база может мгновенно сопоставить данные с другой таблицей.

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1. **Капкан размножения пустоты при несовпадении индексов:**
   Если ты складываешь два `Series`, и в одном из них есть метка, которой нет в другом, Pandas не выдаст ошибку. Он молча запишет в результат смертоносный `NaN` (Not a Number) [91.24]:
   ```python
   s1 = pd.Series([1], index=["стык_01"])
   s2 = pd.Series([1], index=["стык_02"])
   res = s1 + s2 
   # Результат: стык_01: NaN, стык_02: NaN. Данные стерты пустотой!
   ```
   * *Инструмент защиты:* Если нет уверенности в 100% совпадении справочников, используй метод `.add()` с явным указанием дефолтного значения замены (полный аналог `COALESCE` в SQL):
   ```python
   res = s1.add(s2, fill_value=0) # Несовпадающие метки приравняются к 0, расчет спасен
   ```

2. **Ловушка дублирующихся индексов:**
   В отличие от стандартного словаря Python, индекс в Pandas `Series` **может содержать дубликаты**. Если ты попытаешься дернуть значение по дублирующемуся ключу, Pandas вернет не одну строку, а новый под-объект `Series`. Это ломает логику пайплайна, ожидавшего одну конкретную цифру.
   * *Инструмент проверки (ОТК):* Перед использованием индекса как уникального ключа, всегда проверяй его на стерильность:
   ```python
   if not joints.index.is_unique:
       print("Внимание: Нарушена уникальность ключей! Обнаружены дубли.")
   ```

### КРАТКИЙ ИНВЕНТАРНЫЙ ИТОГ ДЛЯ ТВОЕЙ КОРОБКИ:
* **`Series`** — это спарка из хэш-карты индекса (скорость поиска) и жесткого вектора NumPy (скорость математики).
* Береги однородность типов данных (`dtype`). Появление текста в числовой колонке ломает векторную память и раздувает RAM.
* Всегда контролируй уникальность индексов, чтобы избежать лавинообразного размножения `NaN`-пустот при математических операциях [91.24].
