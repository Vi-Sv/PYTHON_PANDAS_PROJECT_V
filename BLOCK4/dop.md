## Дополнение. Инструмент №1: DateTime — Временные оси и хронологические замки (pd.to_datetime())

В реальных логах снабжения и АОСР даты — это текстовый хаос. Сметчики и системы пишут их в разнородных форматах: `31.05.2026`, `2026-06-15`, или `12/04/25`. Если оставить их в виде строк (`object`), базы и Pandas не смогут построить хронологию: для компьютера строка `"31.05.2026"` чисто по алфавиту будет «больше», чем `"01.06.2026"`. Нарастающий итог и скользящие окна превратятся в мусор.

#### 1. Физика в RAM
Метод `pd.to_datetime()` — это прецизионный преобразователь временных осей.
```python
df["fact_date"] = pd.to_datetime(df["fact_date"], format="%d.%m.%Y", errors="coerce")
```
*   **Что происходит в оперативной памяти:** Pandas полностью уничтожает текстовый вектор `object`. Каждая ячейка столбца переводится в жесткий 64-битный формат целых чисел типа `datetime64[ns]`. Под капотом компьютер хранит дату как **количество наносекунд**, прошедших с 1 января 1970 года. 
*   **Параметр-ликвидатор `errors='coerce'`:** Если в ячейку даты просочился мусор или текст `"нет данных"`, плавильная печь не взорвется. Этот параметр принудительно перехватит ошибку и молча запишет на место мусора стерильный маркер системной пустоты `NaT` (Not a Time — аналог `NaN` для дат).

#### 2. Зеркало SQL
Преобразование в `datetime64` в Pandas — это стопроцентное зеркало оператора приведения типов в СУБД:
```sql
SELECT CAST(fact_date AS TIMESTAMP) FROM supply_logs;
```

#### 3. Капканы грязного ввода (ОТК)
*   **Капкан скрытого смещения дней и месяцев:** По умолчанию американские библиотеки читают дату в формате `MM/DD/YYYY` (Месяц/День/Год). Если у тебя в файле написано `04.05.2026` (Четвертое мая), Pandas без явного указания параметра `format` или `dayfirst=True` прочитает это как Пятое апреля. Хронология пайплайна бесшумно разъедется.
*   **Инструмент защиты:** Всегда жестко прописывай маску формата через синтаксические маркеры (например, `%d.%m.%Y`, где `%d` — день, `%m` — месяц, `%Y` — четырехзначный год).

## Дополнение. Инструмент №2: Метод .apply() — Хирургический построчный резак

Бывают нестандартные задачи сметного аудита, которые невозможно решить стандартными векторными методами Pandas. Например, когда тебе нужно применить сложное логическое разветвление, зависящее одновременно от трех разных столбцов (Материал + Объём + Статус). Для таких уникальных операций используется метод `.apply()`.

#### 1. Физика в RAM
Метод `.apply()` — это мост, который берет твою кастомную функцию (`def`) и начинает принудительно прогонять сквозь неё таблицу.
```python
def check_pto_limits(row):
    if row["category"] == "цемент" and row["quantity_fact"] > 100:
        return "Перерасход"
    return "В пределах лимита"

df["limit_status"] = df.apply(check_pto_limits, axis=1)
```
*   **Что происходит в оперативной памяти:** В отличие от быстрых векторов NumPy, метод `.apply(..., axis=1)` работает **построчно**. На каждом шаге (на каждой строке) Pandas вынужден создавать временный объект `Series`, передавать его в функцию, забирать результат и склеивать их обратно. 

#### 2. Главный капкан: Физический износ памяти и скорость
*   **Дефект:** Метод `.apply()` — это самый медленный инструмент в Pandas. По сути, это обычный скрытый цикл `for`, замаскированный под красивую команду. На массивах в 10 миллионов строк `.apply()` заставит сервер задохнуться от нехватки тактовой частоты процессора.
*   **Инструмент защиты (ОТК):** Используй `.apply()` только тогда, когда задачу физически невозможно решить через быстрые векторные переключатели `np.where` (которые мы уложили в Блок 5.1). Если можно решить через `np.where` — `apply` запрещен.

#### 3. Зеркало SQL
Метод `.apply(..., axis=1)` — это точное зеркало использования **Кастомных пользовательских функций (UDF — User Defined Functions)** в SQL. Когда ты пишешь на PL/pgSQL свою функцию и вызываешь её внутри SELECT:
```sql
SELECT check_pto_limits(category, quantity_fact) FROM supply_logs;
```
СУБД PostgreSQL точно так же переходит на построчный перебор (Row-by-row processing), замедляя выполнение плана запроса, так как не может задействовать векторную параллелизацию.
