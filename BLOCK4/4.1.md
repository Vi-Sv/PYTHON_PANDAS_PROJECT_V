### АНАТОМИЯ ИНСТРУМЕНТОВ БОРЬБЫ С ПУСТОТОЙ: УПРАВЛЕНИЕ ДЕФЕКТАМИ

Когда данные прошли через шлюзы импорта, все пропущенные ячейки в Pandas маркируются системными флагами: `None` (для текста) или `NaN` (для чисел) [91.24]. Помня физику RAM, эти пустоты ведут себя коварно: любая математическая операция с `NaN` (например, `5 + NaN`) бесшумно возвращает `NaN`, стирая твои итоговые суммы [91.24].

Для зачистки этих зон у тебя есть три жестких прецизионных инструмента.

#### 1. Инструмент №1: Локатор `.isna()` (Рентген и аудит пустоты)
Этот метод сканирует таблицу и возвращает маску (такую же матрицу), где на месте каждой пустоты загорается логическая лампочка `True`, а на месте данных — `False`.

*   **Физика работы в RAM:** Он проверяет битовую маску каждого вектора NumPy в памяти. Сам по себе он отчет не меняет, но служит идеальным ситом для фильтрации.
```python
# Посчитать точное количество дыр в каждом столбце (ОТК-контроль)
print(df.isna().sum())

# Вырезать из таблицы только те строки, где в столбце "fact_date" сидит дыра
empty_rows = df[df["fact_date"].isna()]
```

#### 2. Инструмент №2: Хирургический нож `.dropna()` (Тотальное вырезание брака)
Этот метод полностью удаляет из таблицы строки или столбцы, в которых обнаружена хотя бы одна пустота.

*   **Физика работы в RAM:** Метод **никогда** не удаляет строки прямо внутри старого блока памяти. Он сканирует индексы, находит чистые строки, копирует их в совершенно новый, непрерывный блок оперативной памяти и возвращает тебе новую «стерильную» таблицу.
*   **Параметры жесткого контроля:**
    *   `axis=0` (по умолчанию) — вырезает горизонтальную строку целиком.
    *   `axis=1` — вырезает вертикальный столбец целиком, если там есть хоть одна дыра.
    *   `subset=["название_колонки"]` — зональный контроль. Приказывает резать строку только в том случае, если пустота сидит в конкретно указанном критически важном столбце (например, `material_id` или `price`), игнорируя дыры в необязательных полях (например, в примечаниях).

```python
# Удалить только те строки, где критически пуст столбец с кодом ТМЦ
df_clean = df.dropna(subset=["material_code"], axis=0)
```

#### 3. Инструмент №3: Ультимативный сумматор `.fillna()` (Заплатка пустоты — Твоя «Коала»)
Это твой прямой, зеркальный и самый ходовой аналог SQL-функции `COALESCE`. Он не уничтожает строки, а «затягивает» дыры дефолтными значениями.

*   **Физика работы в RAM:** Он находит ячейки со значениями `NaN/None` и перезаписывает их физические адреса на адреса переданных тобой констант.
*   **Способы применения:**
    *   *Плоская замена:* `df.fillna(0)` — зальет нулями вообще все дыры во всех столбцах таблицы. Это опасно, так как текстовые колонки тоже получат числовой ноль.
    *   *Специфицированная замена (Инженерный стандарт):* Передача словаря, где под каждый прут-столбец подбирается своя изолированная заплатка.

```python
# Прецизионная затяжка дыр по правилам финотчета холдинга
df = df.fillna({
    "quantity_fact": 0,             # Числовой NULL в объеме превращаем в жесткий 0
    "status": "not_verified",        # Текстовый NULL заменяем на дефолтный статус
    "comment": "нет примечания"     # Зачищаем пустоту в комментариях
})
```

### ЗЕРКАЛО SQL

Вся триада инструментов работы с пустотой в Pandas зеркально отражает предикаты и функции стандарта ANSI SQL:
*   Команда `df[df["status"].isna()]` — это точное соответствие фильтрации:
    ```sql
    SELECT * FROM supply_logs WHERE status IS NULL;
    ```
*   Команда `df.fillna({"quantity_fact": 0})` — это чистый, стопроцентный аналог функции `COALESCE`:
    ```sql
    SELECT COALESCE(quantity_fact, 0) AS quantity_fact FROM supply_logs;
    ```

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1.  **Капкан бездумной перезаписи на месте (`inplace=True`):**
    Многие старые учебники советуют писать `df.dropna(inplace=True)` или `df.fillna(0, inplace=True)`.
    *   *В чем дефект:* Флаг `inplace=True` — это опасный синтаксический обман. Он не экономит оперативную память под капотом. Память всё равно выделяется под скрытую копию, но при этом ломается цепочка выполнения пайплайна, и ты рискуешь получить тот самый страшный капкан `SettingWithCopyWarning`, который мы разбирали в Блоке 2 [91.24].
    *   *Инструмент защиты (Стерильный код):* Всегда явно переприсваивай таблицу через знак равенства:
    ```python
    df = df.fillna({"volume": 0}) # Безопасно, прозрачно, предсказуемо для RAM
    ```

### КРАТКИЙ ИНВЕНТАРНЫЙ ИТОГ ДЛЯ ТВОЕЙ КОРОБКИ:
*   Никогда не пускай сырые таблицы в математический контур, пока не проверишь их рентгеном `.isna()`.
*   **`.dropna(subset=[...])`** — используй для жесткой отсечки строк, в которых отсутствуют критические идентификаторы (бизнес-ключи).
*   **`.fillna({...})`** — твой персональный `COALESCE`. Всегда передавай в него словарь для раздельного контроля типов числовых и текстовых столбцов.
