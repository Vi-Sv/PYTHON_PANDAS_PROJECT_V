### АНАТОМИЯ ИНСТРУМЕНТА: ЛИТЬЕ ТИПОВ В ВЕКТОРНОЙ ПАМЯТИ

Метод `.astype()` — это плавильная печь для типов данных в Pandas. Он берет существующий вектор ячеек в RAM и принудительно перестраивает структуру его байтов под новый заданный шаблон.

#### 1. Физика базового литья типов
Когда ты вызываешь команду:
```python
df["material_id"] = df["material_id"].astype("int64")
```
*   **Физика в RAM:** Процессор полностью пересобирает вектор NumPy. Каждая ячейка столбца принудительно переводится в формат 64-битного целого числа. Если в процессе литья алгоритм наткнется на строку или пустоту `NaN`, которую невозможно упаковать в целое число, печь взорвется — пайплайн аварийно остановится с ошибкой `ValueError`.

#### 2. Проблема неточного Float (Почему исчезают деньги)
По умолчанию Pandas переводит все дробные числа и ячейки с пустыми значениями в тип данных `float64` (числа с плавающей точкой) [91.24].
*   **В чем скрытый дефект:** Тип данных `float` устроен на уровне процессора по стандарту IEEE 754. Он хранит числа в двоичной системе счисления, из-за чего **физически не может точно представить большинство десятичных дробей**.
```python
# Физический парадокс float в RAM компьютера:
print(0.1 + 0.2) # Напечатает: 0.30000000000000004
```
В коммерческой аналитике, сметных расчетах холдингов и финтехе этот микроскопический хвост `...0004` на миллионах строк суммируется и превращается в огромные недостачи и расхождения баланса [91.11, 91.24].

#### 3. Бескомпромиссный перевод в Decimal (Инструмент Ювелира)
Чтобы выжечь эту погрешность из финансовых отчетов, мы обязаны уйти от процессорного `float` и перевести данные на тип фиксированной точности — **`Decimal`** (аналог `NUMERIC` в СУБД) [91.11, 91.24].

```python
from decimal import Decimal
import pandas as pd

# 1. Сначала выжигаем текстовый мусор и переводим строки в чистый float
df["price"] = df["price"].str.replace(r"[^\d\.]", "", regex=True)

# 2. Бескомпромиссно отливаем вектор в точные коммерческие объекты Decimal
df["price"] = df["price"].apply(lambda x: Decimal(str(x)) if pd.notna(x) else Decimal("0.00"))
```
*   **Физика в RAM:** Мы отказываемся от быстрого, но неточного двоичного вектора `float`. Каждая ячейка теперь содержит ссылку на независимый объект `Decimal`, который считает дроби точно так же, как человек на бумаге — в десятичной системе. Округления и пропажа копеек полностью заблокированы [91.11, 91.24].

### ЗЕРКАЛО SQL

Принудительное литье типов и уход в `Decimal` в Pandas — это точное зеркало оператора `CAST` и жестких типов данных в СУБД:
*   Команда `df["material_id"].astype('int64')` — это:
    ```sql
    SELECT CAST(material_id AS BIGINT) FROM supply_logs;
    ```
*   Перевод вектора в объекты `Decimal` — это использование прецизионного коммерческого типа `NUMERIC`, который законодательно закреплен во всех финансовых структурах [91.11, 91.24]:
    ```sql
    SELECT CAST(price AS NUMERIC(15, 2)) FROM supply_logs;
    -- Запрещает серверу использовать приближенный тип FLOAT/REAL
    ```

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1.  **Капкан безвозвратной потери данных при грубом литье типов:**
    Если в столбце объемов `quantity` лежали дробные числа (например, `15.50 м3`), а ты применил жесткое литье в целое число:
    ```python
    df["quantity"] = df["quantity"].astype("int64")
    ```
    *   *В чем дефект:* Pandas не выдаст ошибку и не округлит числа по правилам математики. Он просто **молча отрежет дробный хвост**. Число `15.50` превратится в `15`. Пол-куба материала бесшумно испарились из отчета.
    *   *Инструмент защиты:* Всегда делай предварительную проверку или используй метод явного математического округления `.round()` перед переводом в `int`.

### КРАТКИЙ ИНВЕНТАРНЫЙ ИТОГ ДЛЯ ТВОЕЙ КОРОБКИ:
*   **`.astype()`** — инструмент жесткого, принудительного изменения структуры вектора памяти. Требует стерильных данных без скрытого текста.
*   **Тип `float`** — категорически запрещен в финансовых и сметных итоговых отчетах из-за накапливающейся погрешности двоичного округления [91.11, 91.24].
*   **`Decimal`** — твой главный калибр для работы с деньгами и точными объемами [91.11, 91.24]. Перевод осуществляется через строковое представление `Decimal(str(x))`, чтобы `float` не успел нагадить своей погрешностью в памяти компьютера.
