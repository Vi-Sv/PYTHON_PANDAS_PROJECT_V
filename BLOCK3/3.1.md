### АНАТОМИЯ ИНСТРУМЕНТОВ ПРИЕМА: ШЛЮЗЫ В RAM

Библиотека Pandas имеет два главных шлюза для импорта внешних табличных массивов:
1.  **`pd.read_csv()`** — скоростной текстовый парсер. Он читает плоские файлы, где строки разделены переносом, а столбцы — запятой, точкой с запятой или табуляцией. Работает на низком уровне C (Си) со скоростью пулемета.
2.  **`pd.read_excel()`** — тяжелый шлюз-трансформатор. Под капотом он запускает сторонние движки (например, `openpyxl`), которые сначала долго распаковывают XML-структуру файла `.xlsx`, пересчитывают его формулы и только потом переводят в плоскую матрицу Pandas. Требует в 3–4 раза больше памяти, чем CSV.

#### 1. Физика параметров-перехватчиков (Жесткие барьеры на входе)
Чтобы защитить оперативную память от взрыва, мы обязаны настроить параметры-фильтры прямо внутри команды чтения. Мы не пускаем данные в RAM, пока не выставим им жесткие рамки [91.24].

*   **`usecols` (Физическая отсечка лишнего веса)**
    Зачем загружать в память 50 столбцов огромного сметного отчета, если для расчета отклонений ГПР тебе нужны только три [91.24]? Параметр `usecols` принимает список конкретных названий или индексов колонок.
    *   *Физика в RAM:* СУБД/Парсер физически игнорирует не указанные столбцы на этапе чтения диска. В оперативную память заходят только целевые «прутья» данных, экономя до 80% объема RAM [91.24].
*   **`dtype` (Принудительное литье типов на лету)**
    Параметр принимает словарь формата `{"название_колонки": тип_данных}`.
    *   *Физика в RAM:* Выставляет жесткий шаблон для вектора NumPy. Если Pandas видит код ТМЦ `004501`, по умолчанию он отбросит нули и запишет число `4501`. Если указать `dtype={'material_code': str}`, Pandas выделит ячейки под строки и сохранит ведущие нули в их стерильном первозданном виде [91.24].
*   **`na_values` (Ловушка маскировки пустоты)**
    Сметчики и операторы обожают маскировать отсутствие данных своими кастомными маркерами: пишут в ячейках `"Н/Д"`, `"нет"`, `"-"`, `"empty"`, или просто ставят три пробела `"   "`. По умолчанию Pandas их не распознает как пустоту и запишет как текст, превратив всю числовую колонку в тяжелый тип `object` [91.24].
    *   *Физика в RAM:* Параметр принимает список текстовых масок `na_values=["Н/Д", "-", "   "]`. Встретив их при чтении, парсер на лету заменяет этот мусор на физический системный маркер пустоты `NaN` (для чисел) или `None` (для текста) [91.24].

```python
import pandas as pd

# Контур жесткого приема сырого лога снабжения
df = pd.read_csv(
    "supply_raw_log.csv",
    sep=";",                        # Указываем жесткий разделитель колонок
    usecols=["log_id", "code", "volume"],  # Забираем только 3 целевых столбца из 20
    dtype={"code": str, "log_id": int},    # Сохраняем ведущие нули кодов, фиксируем ID
    na_values=["-", "нет данных", "Н/Д"]   # Выжигаем текстовый мусор, переводя его в NaN/None
)
```

#### 2. Зеркало SQL
Параметры-перехватчики в `pd.read_csv / read_excel` — это точное зеркало **фильтрации и проекции в блоке `SELECT` на уровне СУБД**.
Когда ты пишешь в СУБД:
```sql
SELECT log_id, CAST(code AS VARCHAR) 
FROM supply_logs 
WHERE code IS NOT NULL;
```
* `SELECT log_id, code` — это твой параметр `usecols`.
* `CAST(code AS VARCHAR)` — это твой параметр `dtype`.
* `WHERE code IS NOT NULL` (и обработка пустых строк) — это твой контур `na_values`.

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1.  **Капкан скрытого смещения строк при несовпадении разделителей:**
    Если в CSV-логе разделителем является точка с запятой `;`, а ты забыл указать параметр `sep=';'`, Pandas по умолчанию применит запятую.
    *   *В чем дефект:* Таблица не упадет с ошибкой. Pandas просто склеит всю строку со всеми точками с запятой в одну гигантскую текстовую колонку `object`. Твой пайплайн продолжит выполняться, но на этапе первой же математической операции всё рухнет.
    *   *Инструмент защиты:* Всегда явно прописывай разделитель `sep` для CSV и никогда не полагайся на автоматику.

2.  **Ловушка "Многоэтажных шапок" в Excel (`header`):**
    Сметчики обожают делать вверху таблиц красивые «шапки» из объединенных ячеек, логотипов компании и пустых строк, а реальные технические названия столбцов начинаются только с 5-й или 6-й строки.
    *   *В чем дефект:* Если прочитать файл напрямую, Pandas возьмет мусорный логотип или пустую строку в качестве названий колонок, а реальные имена столбцов уйдут внутрь данных как обычные строки.
    *   *Инструмент защиты:* Используй параметр-перехватчик `header`. Он указывает, с какой конкретно строки (индексация с нуля) начинается чистая матрица названий:
    ```python
    df = pd.read_excel("смета.xlsx", header=4) # Начнет чтение строго с 5-й строки файла
    ```
