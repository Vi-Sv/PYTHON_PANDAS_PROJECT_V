### ИНСТРУМЕНТ №1: ПРОСТРАНСТВО ИМЕН И ОБЛАСТЬ ВИДИМОСТИ (ГРАНИЦЫ ДОСТУПА)

Представь себе строительную площадку. У тебя есть общий склад объекта (Глобальная область) и изолированные бытовки отдельных бригад (Локальная область). Переменная с одним и тем же именем, например `volume`, на общем складе и внутри бытовки — это два совершенно разных физических объекта.

#### 1. Физика в RAM (Система изолированных контейнеров)
Каждое пространство имен (Namespace) в Python под капотом — это уже знакомый тебе **Словарь (`dict`)**, где ключом является имя переменной, а значением — адрес ее физического размещения в памяти.
Когда программа стартует, создается **Глобальный словарь (Global)**. Но как только управление заходит внутрь функции, Python мгновенно изолирует память и создает временный **Локальный словарь (Local)**.

```python
volume = 150  # Глобальная переменная (на общем складе объекта)

def calculate_concrete():
    volume = 12  # Локальная переменная (внутри изолированной бытовки функции)
    print(volume) # Напечатает 12 (Python сначала смотрит в локальный словарь)

calculate_concrete()
print(volume)     # Напечатает 150 (Глобальный склад остался нетронутым)
```

#### 2. Порядок поиска имён: Правило LEGB
Когда ты вызываешь переменную внутри функции, Python ищет её имя строго по цепочке, от ближнего круга к дальнему:
1. **L (Local)** — Ищет во временном локальном словаре самой функции.
2. **E (Enclosing)** — Ищет внутри объемлющих (родительских) функций, если это вложенная структура.
3. **G (Global)** — Ищет в глобальном словаре текущего файла.
4. **B (Built-in)** — Ищет в системных функциях самого Python (например, `print`, `sum`).
* Если имя не найдено ни в одном словаре — система выбрасывает аварийный флаг `NameError`. Локальные словари функций уничтожаются из RAM сразу после того, как функция завершила работу (`return`).

#### 3. Зеркало SQL
Область видимости в Python — это зеркало **алиасов и изолированных пространств в CTE и подзапросах**. Когда ты пишешь:
```sql
WITH checked_supply AS (
    SELECT id, quantity AS volume FROM supply_logs -- Локальный алиас volume
)
SELECT volume FROM checked_supply;
```
Внешний запрос ничего не знает о том, как назывались исходные столбцы внутри CTE `checked_supply`. Для него существует только то пространство имен, которое вернул внутренний контур. Переменные внутри CTE изолированы от внешнего SELECT.

### ИНСТРУМЕНТ №2: КАСТОМНЫЕ ФУНКЦИИ И ДИНАМИЧЕСКИЕ ПРИЕМНИКИ (*ARGS / **KWARGS)

Функция (`def`) — это твой личный автоматизированный цех. Ты подаешь на вход сырье (аргументы), внутри происходит алгоритмическая плавка, а на выходе ты получаешь готовое изделие (`return`).
Но в реальном секторе на вход функции может прилететь хаос: то 2 параметра, то 10, то сметные коды неизвестной длины. Для этого в Python предусмотрены динамические приемники данных — «всеядные ловушки» `*args` и `**kwargs`.

#### 1. Механика `*args` — Ловушка для позиционных параметров
Когда ты ставишь звездочку перед именем аргумента (имя может быть любым, но стандарт — `args`), ты приказываешь Python: *«Все неименованные параметры, которые прилетят на вход, упакуй в один неизменяемый список — Кортеж (Tuple)»*.

```python
def sum_materials(*args):
    # В RAM args упакован как кортеж: (10, 25, 40)
    total = sum(args) 
    return total

print(sum_materials(10, 25, 40)) # Передали 3 числа, функция сожрала их и вернула 75
```
* **Физика в RAM:** Компьютер не резервирует под каждый аргумент отдельную переменную. Он динамически создает один объект в памяти, куда последовательно складывает ссылки на входящие данные.

#### 2. Механика `**kwargs` — Ловушка для именованных параметров (Справочников)
Две звездочки (Keyword Arguments) приказывают Python: *«Все именованные параметры, переданные через знак равенства `ключ=значение`, упакуй в **Словарь (`dict`)**»*. Это идеальный инструмент для передачи кастомных конфигураций, настроек или строк сметного реестра.

```python
def audit_log(**kwargs):
    # В RAM kwargs лежит как словарь: {"number": 408, "status": "verified"}
    for key, value in kwargs.items():
        print(f"Поле {key} имеет значение {value}")

audit_log(number=408, status="verified")
```

#### 3. Зеркало SQL
Динамические аргументы в Python — это аналог работы с **динамическим SQL или массивами/JSON** в базах данных. Когда ты в PostgreSQL передаешь в функцию объект типа `JSONB`:
```sql
SELECT * FROM my_function('{"material_id": 102, "fact": 15.5}'::jsonb);
```
Функция внутри базы на ходу парсит ключи и значения из одного входящего контейнера, точно так же, как `**kwargs` разбирает именованные параметры в Python.

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1. **Капкан изменяемых дефолтных аргументов (Классический баг джунов):**
   Никогда не передавай пустой список в качестве значения по умолчанию. 
   ```python
   def add_repair(joint, log_list=[]): # Смертельный капкан в RAM
       log_list.append(joint)
       return log_list
   ```
   * *В чем дефект:* Пустой список `[]` создается в памяти **один раз** при объявлении функции. При каждом новом вызове Python будет использовать тот же самый физический адрес памяти, и твои данные начнут накапливаться и перемешиваться между разными вызовами отчетов.
   * *Инструмент защиты (Стерильный код):* Используй дефолтное значение `None`:
   ```python
   def add_repair(joint, log_list=None):
       if log_list is None:
           log_list = [] # Список создается заново в RAM при каждом вызове
       log_list.append(joint)
       return log_list
   ```

2. **Ловушка забытого `return`:**
   Если внутри функции ты выполнил расчет, но забыл в конце написать команду `return`, функция вернет пустоту — объект `None`. Твои вычисления сгорят в оперативной памяти и не передадутся дальше по цепочке пайплайна.

### КРАТКИЙ ИНВЕНТАРНЫЙ ИТОГ ДЛЯ ТВОЕЙ КОРОБКИ:
* **Область видимости** — жестко разграничивает память. Что создано внутри функции — умирает внутри функции. Глобальный склад трогать только в крайних случаях.
* `*args` — твоя ловушка для неограниченного списка параметров. В RAM лежит как **кортеж**.
* `**kwargs` — твоя ловушка для именованных параметров и конфигураций. В RAM лежит как **словарь**.
