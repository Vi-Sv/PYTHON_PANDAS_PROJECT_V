## Пункт 1.3. Логические операторы и капканы ветвления (if-elif-else). Почему None в Python — это не то же самое, что NULL в SQL.

### ИНСТРУМЕНТ №1: КАПКАНЫ ВЕТВЛЕНИЯ И ЛОГИКА ОЦЕНКИ (IF-ELIF-ELSE)

Конструкция `if-elif-else` — это стрелочный перевод на цифровой магистрали. Python оценивает выражение на истинность и направляет поток данных по одному из изолированных путей.

#### 1. Физика в RAM (Ленивые вычисления и короткое замыкание)
Когда ты соединяешь несколько условий операторами `and` (И) или `or` (ИЛИ), Python экономит такты процессора и использует механизм **Short-circuit evaluation (короткое замыкание вычислений)**.
* **При операторе `or`:** Если первое же условие оказалось истинным (`True`), Python **мгновенно прекращает** дальнейшую проверку и заходит внутрь блока. Ему плевать, что написано дальше, процессор не тратит на это время.
* **При операторе `and`:** Если первое же условие оказалось ложным (`False`), вычисления останавливаются на месте, а весь остальной хвост условий игнорируется.

```python
# Если макрос нашел пустую строку, тяжелая функция проверки геометрии даже не запустится
if row_is_empty or heavy_geometry_audit(row):
    pass
```

#### 2. Неявное приведение к True/False (Что Python считает пустотой)
Вам не обязательно писать `if len(my_list) == 0:`. Python устроен так, что любой объект в логическом контексте скрыто приводится к Истине или Лжи.
* **Абсолютный Ноль (Ложь / False):** Логическое реле сработает как ложь, если объект является: числовым нулем (`0`, `0.0`), пустой строкой (`""`), пустым списком (`[]`), пустым словарем (`{}`) или объектом `None`.
* **Все остальное (Истина / True):** Любое заполненное значение (даже строка с одним пробелом `" "` или список с единственным нулем `[0]`) — это железное `True`.

### ИНСТРУМЕНТ №2: МАТЕМАТИЧЕСКИЙ БАТТЛ — NONE VS NULL

Это главная точка тектонического разлома между Python и SQL. Ошибка в этой логике крадет копейки в финотчетах холдингов и сдвигает хронологию поставок [91.11, 91.24].

#### 1. Что такое NULL в SQL? (Неизвестность)
В реляционных базах данных `NULL` — это **не значение**, это отсутствие значения. Это маркер неопределенности («черный ящик»). Из-за этого в SQL действует **трехзначная логика (3VL)**.
Если ты спросишь у СУБД: `NULL = NULL`, она ответит не `True`, она вернет `NULL` (Неизвестно). Ты не можешь сравнивать неизвестность с неизвестностью через знак равенства, для этого ты использовал специальный прецизионный инструмент `IS NULL`.

#### 2. Что такое None в Python? (Конкретный физический Объект)
В Python `None` — это **реальный, физический объект** в оперативной памяти, представляющий собой пустоту. Это синглтон (единственный в своем роде экземпляр класса `NoneType`). У него есть конкретный адрес в RAM.
Поэтому в Python сравнение `None == None` абсолютно законно и **всегда возвращает `True`**.

```python
# Физическое сравнение в Python
fact_date = None
plan_date = None

print(fact_date == plan_date) # Напечатает True! (В SQL NULL = NULL вернул бы ложь/NULL)
```

#### 3. Зеркало SQL (Правило моста)
Когда Pandas выкачивает таблицу из SQL-базы в RAM компьютера, все маркеры `NULL` из текстовых столбцов превращаются в объект `None`. Но если `NULL` сидел в числовом столбце (например, объемы поставок или суммы транзакций), Pandas не может превратить его в `None`, потому что числовая матрица требует однородности. 
* Числовой `NULL` в Pandas превращается в **`NaN` (Not a Number)** — физический тип данных `float`. Это порождает страшные капканы при фильтрации.

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1. **Капкан тождественности (`== None` vs `is None`):**
   Никогда не проверяй пустоту в Python через двойное равенство `if x == None:`.
   * *В чем дефект:* Сторонний программист (или кривая библиотека) может перегрузить магический метод равенства внутри кастомного класса, и оператор `==` выдаст ложь, даже если объект пуст.
   * *Инструмент защиты (Стерильный код):* Проверяй пустоту исключительно через оператор идентичности `is`. Оператор `is` сравнивает не значения, а напрямую физические адреса в RAM. Это работает со скоростью света и неуязвимо для багов:
   ```python
   if volume_fact is None:
       volume_fact = 0  # Жесткая зачистка, аналог COALESCE
   ```

2. **Ловушка «Ложной пустоты» при очистке строк:**
   Классическая авария пайплайна, когда сметчик ввел в ячейку объема пробел `" "`. 
   ```python
   volume = " "
   if not volume:
       print("Данные отсутствуют") # Код СЮДА НЕ ЗАЙДЕТ! Строка с пробелом — это ИСТИНА (True).
   ```
   * *Инструмент защиты:* Всегда делай предварительную зачистку хвостовых пробелов (Data Stripping) до логического анализа:
   ```python
   if not volume.strip():
       print("Данные отсутствуют") # Теперь отработает безупречно
   ```

### КРАТКИЙ ИНВЕНТАРНЫЙ ИТОГ ДЛЯ ТВОЕЙ КОРОБКИ:
* **Логика условий** работает лениво (Short-circuit). Разворачивай условия так, чтобы самая быстрая проверка шла первой.
* `None` в Python — это осязаемый объект пустоты, он равен самому себе (`None is None` ➔ `True`).
* Помни о мосте: при импорте в Pandas текстовый `NULL` станет `None`, а числовой `NULL` станет `NaN` (типом `float`), что может незаметно превратить твои целые числа `INT` в дробные `FLOAT`.
