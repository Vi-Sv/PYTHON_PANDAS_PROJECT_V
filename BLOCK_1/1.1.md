# БЛОК 1. АНАТОМИЯ ОКРУЖЕНИЯ И ТИПЫ ДАННЫХ (ФИЗИКА RAW PYTHON)
## Пункт 1.1. Выделение памяти под базовые объекты: Списки (Lists) vs Словари (Dicts). Логика индексов и хэш-таблиц.

Добро пожаловать к первому верстаку. Прежде чем строить тяжелые цифровые магистрали в Pandas, мы обязаны заглянуть под капот самого языка Python и разобраться, как компьютер выделяет физическую память (RAM) под две главные коробки для хранения данных — Списки (`list`) и Словари (`dict`). 

Здесь нет магии. Есть только структура, адреса ячеек и скорость доступа. Если ты поймешь физику этих двух инструментов, ты никогда не повесишь сервер неэффективным кодом.

---

### ИНСТРУМЕНТ №1: СПИСКИ (LISTS) — ЦЕПОЧКА СВЯЗАННЫХ КИРПИЧЕЙ

Представь себе длинную стену, в которую строго по очереди уложены кирпичи. Каждый кирпич — это элемент списка, и у каждого есть свой жесткий порядковый номер (индекс), начиная строго с нуля.

#### 1. Физика в RAM (Что происходит внутри памяти)
Когда ты создаешь список в Python, например:
```python
my_list = ["стык_01", "стык_02", "стык_03"]
```
Компьютер не просто бросает эти строки в память. Он находит в RAM **непрерывный свободный блок ячеек**. В этом блоке друг за другом резервируются адреса, указывающие на твои элементы. 

Главное свойство списка — **строгая последовательность**. Компьютер точно знает, где сидит первый элемент, и чтобы найти, например, 100-й элемент, ему не нужно перебирать первые 99. Он берет адрес начала списка, прибавляет к нему 100 и мгновенно прыгает в нужную ячейку памяти. 
* В ИТ-индустрии такая скорость доступа по индексу называется **O(1)** — это значит «мгновенно», независимо от длины списка.

#### 2. Главный капкан списков: Поиск по значению
А теперь представь, что индекс тебе неизвестен. Перед тобой список из миллиона строк (например, транзакционный лог), и тебе нужно проверить, есть ли там запись `"стык_999"`.
```python
if "стык_999" in my_list:
    pass
```
Вот здесь список превращается в зыбучие пески. Компьютер **не знает**, где лежит это значение. У него нет индекса. Что он делает? Он берет первый кирпич, смотрит на него: «Это стык_999?» — Нет. Берет второй, третий... и так до самого конца. 
* Если элемент лежит в самом хвосте списка из миллиона строк, компьютер сделает миллион шагов. Этот долгий поиск называется **O(N)**. Если запускать такой поиск внутри цикла — сервер захлебнется и задымится.

#### 3. Зеркало SQL
В реляционных базах данных список без индекса — это обычная сырая таблица без первичного ключа (Primary Key). Когда ты пишешь:
```sql
SELECT * FROM supply_logs WHERE status = 'verified';
```
Если на столбце `status` нет индекса, СУБД делает страшную операцию — **Full Table Scan** (полное последовательное сканирование диска). Она перебирает каждую строчку сверху вниз, точно так же, как Python перебирает элементы в длинном списке.

### ИНСТРУМЕНТ №2: СЛОВАРИ (DICTS) — ИДЕАЛЬНЫЙ СКЛАД С ХЭШ-ТАБЛИЦЕЙ

Словарь в Python — это структура формата «Ключ: Значение». Но под капотом у него сидит самый мощный инженерный механизм — **Хэш-таблица**. Забудь про порядковые номера (0, 1, 2). Здесь правит бал математика.

#### 1. Физика в RAM (Что происходит внутри памяти)
Когда ты записываешь элемент в словарь:
```python
my_dict = {"стык_01": "Принято ОТК", "стык_02": "Дефект УЗК"}
```
Компьютер берет твой ключ (например, строку `"стык_01"`) и пропускает его через внутренний математический резак — **Хэш-функцию**. 
Хэш-функция мгновенно превращает любой текст в уникальное число (адрес ячейки памяти). Например, для строки `"стык_01"` она выдает число `7402`. Компьютер сразу идет в ячейку памяти под номером `7402` и укладывает туда значение `"Принято ОТК"`.

#### 2. Скорость без компромиссов
Когда ты спустя время спрашиваешь у словаря: *«Что там по стыку_01?»*
```python
status = my_dict["стык_01"]
```
Python не перебирает словарь сверху вниз. Он снова берет ключ `"стык_01"`, мгновенно вычисляет его хэш (`7402`) и сразу прыгает в ячейку `7402`. 
* Поиск, добавление и удаление в словаре ВСЕГДА происходят мгновенно — за один шаг **O(1)**. Будь в словаре хоть три строки, хоть сто миллионов — скорость поиска по ключу будет одинаковой.

#### 3. Зеркало SQL
Словарь в Python — это зеркальное отображение таблицы с **Первичным ключом (Primary Key)** или уникальным индексом (Unique Index). 
```sql
SELECT status FROM supply_logs WHERE log_id = 4501;
```
Когда в SQL ты ищешь строку по Primary Key, СУБД не сканирует всю таблицу. Она использует индекс (дерево или хэш), чтобы за один-два шага вычислить физический адрес строки на диске и выдать ее результат. Словарь в Python делает ровно то же самое, но внутри оперативной памяти.

### ДЕФЕКТЫ И КАПКАНЫ ГРЯЗНОГО ВВОДА (ОТК-КОНТРОЛЬ)

1. **Капкан неуникального ключа в словаре:**
   В списке ты можешь дублировать элементы сколько угодно. В словаре ключ **обязан быть уникальным**. Если ты попытаешься записать в словарь новый элемент с уже существующим ключом, старые данные будут безвозвратно стерты на лету:
   ```python
   data = {"стык_01": "ОК"}
   data["стык_01"] = "Брак"  # Старое значение "ОК" уничтожено, база перезаписана
   ```
2. **Ловушка отсутствующего ключа (`KeyError`):**
   Если ты попытаешься вытащить из словаря ключ, которого там нет, программа мгновенно упадет в аварийный режим со страшной ошибкой `KeyError`.
   * *Инструмент защиты:* Никогда не дергай данные напрямую через квадратные скобки, если не уверен в стерильности базы. Используй безопасный метод `.get()`. Если ключа нет, он вернет пустоту или твое дефолтное значение (полный аналог `COALESCE` в SQL):
   ```python
   # Если ключа "стык_99" нет, программа не упадет, а вернет строку "Не найдено"
   status = my_dict.get("стык_99", "Не найдено") 
   ```

### КРАТКИЙ ИНВЕНТАРНЫЙ ИТОГ ДЛЯ ТВОЕЙ КОРОБКИ:
* **Список (`list`)** — используй, когда тебе важен строгий порядок элементов, хронология, и ты будешь обращаться к ним по порядковым номерам. Но помни: поиск по тексту внутри большого списка убивает память серверов.
* **Словарь (`dict`)** — используй всегда, когда нужно построить быстрый справочник, реестр или маппинг, где по уникальному коду (ключу) нужно мгновенно вытаскивать информацию.

Первый инструмент уложен в коробку. Логика ясна, физика RAM зафиксирована.
